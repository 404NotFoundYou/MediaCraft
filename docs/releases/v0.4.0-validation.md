# MediaCraft 0.4.0 构建与验证

日期：2026-11-11（Asia/Shanghai）。版本：0.4.0 / versionCode 4。

## 本地构建

- 单元测试 67 项通过，失败、错误和跳过均为 0。
- `lintDebug` 通过；保留依赖更新、KTX 等既有警告。
- Debug APK、AndroidTest APK 和正式签名 Release APK 构建成功。
- 默认源码版本与发布参数均为 0.4.0 / code 4，正式版继续面向 ARM64、最低 Android 11。
- 更新界面测试中的“新版本”样本随当前 versionCode 生成，避免发布升级后把旧版测试数据当作新版本。

## Android 后台测试

测试环境为 Android 16 / API 36 的 `MediaCraft_API36`，使用 `-read-only -no-window -no-audio -no-snapshot`，两核，最终一轮分配 1024 MB 内存。分辨率 540 × 1080、密度 240，未展示模拟器窗口。

直接使用已构建 APK 和 `am instrument -w -r` 执行：

- 全部 28 项仪器测试通过，0 失败；Runner 输出 `OK (28 tests)`，耗时约 35 秒。
- 覆盖图库和重复项复核、重命名锁定预览、操作记录、媒体摘要和质量建议、视频解码、真实系统回收站/恢复与写入授权取消、更新界面和进程恢复，以及新位置详情。
- 位置详情单独复核 2 项通过：自生成 EXIF GPS 图片得到正确 DMS 坐标；无 GPS 图片显示“未记录位置”，不显示地图入口。关闭详情后图库仍可继续操作。
- 测试样本均使用应用创建的唯一前缀 URI / 缓存 JPEG，不对个人媒体扫描或执行写入。

初次 UI 回归发现首个超高 LazyColumn item 内的相册与结果未进入视口，旧测试的点击没有真正选中相册。测试改为有界滚动直到目标实际可见，并断言选中；扫描结束后滚动结果再断言。对比按钮增加组内文件名的无障碍描述，测试明确选择自身样本组。业务期望和确认门槛保持原样。初次失败与最终通过日志均保留。

## 地名与地图

- 系统 Geocoder 对示例坐标返回地名 `Singapore · 80`，地址为 `80 Mandai Lake Rd, Singapore 729826`。这是服务实际结果，不把原型中的“万礼”或 Singapore Zoo 写成固定答案。
- 坐标显示为 `1° 24′ 20.06″ N, 103° 47′ 40.28″ E`。
- WebView 的最终 URL、OpenStreetMap Embedded 标题和 MapLibre Canvas 已核对，Canvas 为 372 × 450 像素。
- 等待异步绘制后记录到 4 个 `tile.openstreetmap.org` 请求，响应均为 HTTP 200。
- 后台截图中地图主体仍为白色，仅版权文字可见。不能据此宣称地图像素绘制成功；可能涉及无窗口图形合成，也可能是渲染链路问题。真机地图视觉验收仍未完成。
- 无 GPS 空态的最终截图中“拍摄位置 / 未记录位置”完整可见，地名、地址和坐标无横向文字裁切。
